Introduction

Steve Jobs is a scalable asynchronous task queue that gives developers a simple way to offload intensive LogicBlox tasks and process these in the background.

Software

Currently, there is a fixed set of software available on the workers:

  • LogicBlox
    • LogicBlox 3.10.15, including Gurobi
    • LogicBlox 4.1.5
    • LogicBlox 4.1.6
    • LogicBlox 4.1.7
    • LogicBlox 4.1.8
  • pdxscience 4.0.0
  • GNU grep, sed, coreutils, binutils, jq

You can use the different platform versions by setting the platform value, e.g. -m platform=4.1.6.

Queues

  • c3-xlarge - Default, 4 vCPU, 7.5GB, 80GB SSD
  • r3-xlarge - 4 vCPU, 30.5GB, 80 GB SSD
  • r3-2xlarge - 8 vCPU, 61GB, 160 GB SSD
  • r3-8xlarge - 32 vCPU, 244GB, 640 GB SSD
  • i2-2xlarge - 8 vCPU, 61GB, 1600 GB SSD

You can use the different queues by setting the job-queue value to the identifier listed above, e.g. -m job-queue=r3-2xlarge.

Getting started!

To start experimenting with Steve Jobs, you need the following:

  • Download lb-steve client
  • Access to the AWS console
  • Set the AWS_ACCESS_KEY and AWS_SECRET_KEY environment variables to AWS API credentials that have access to your S3 buckets.

Extract the client, and add the bin/ subdirectory in the PATH.

Give Steve Jobs access to one of your S3 buckets, e.g. by setting the following bucket policy: 

{
	"Version": "2008-10-17",
	"Id": "Policy1335892530063",
	"Statement": [
		{
			"Sid": "AccountLBJobs",
			"Effect": "Allow",
			"Principal": {
				"AWS": "arn:aws:iam::826045886586:root"
			},
			"Action": ["s3:Get*", "s3:Put*", "s3:List*"],
			"Resource": [
				"arn:aws:s3:::<bucket-name>/*",
				"arn:aws:s3:::<bucket-name>"
			]
		}
	]
}

You can find some trivial examples of job implementations at https://bitbucket.org/logicblox/jobs: 

$ hg clone https://bitbucket.org/logicblox/jobs
$ cd jobs/sample-jobs

Run the following commands to generate a public and private key: 

$ openssl genrsa -out priv.pem 2048
$ openssl rsa -in priv.pem -out pub.pem -pubout
$ openssl pkcs8 -topk8 -inform PEM -outform PEM -in priv.pem -out priv-pkcs.pem -nocrypt

Send the public key pub.pem to lb-jobs@logicblox.com to request access to LB Steve, you will receive a username which we will use in the next step.

Create ~/lb_deployment/config/lb-steve-client.config with the following, which defines the default output location (which is used when a user does not specify a concrete S3 location to put its outputs): 

default_output_prefix = s3://<bucket-name>/tmp

[auth]
user = yourusername
key_file = /path/to/your/priv-pkcs.pem

To run the ancestor example, you can run: 

$ lb-steve upload-impl --impl ancestor -i ./ancestor --wait
{"job_id":"045cbf3e-49d2-40ae-b54a-d0460895b330"}

$ lb-steve create-job --impl ancestor -o output.txt --wait

Metadata

You can attach arbitrary metadata to a job, and this metadata will be available as a JSON file, called metadata.json, in the input data directory (the first argument passed to your run script of your job implementation). An example metadata.json: 

{"job-queue":"c3-xlarge","date":"2015-03-30 11:10:44.927+00:00"}
  • Reserved metadata keys
    • date - Date/time the job was created.
    • job-queue - Job queue to use.
    • timeout - Number of seconds (n) after which a job run will time out. Between 0 and 40000.
    • no-services - If you want to skip starting LB services. Can only be 'true'.

FAQ

  • I can't see the log of a jobs!
    • The log of a job is only available once a job finishes. If there is no log when a job has finished, make sure to check the job status for potential errors. If you have a long running job, you have the possibility to send some status information by logging lines starting with PROGRESS:. These messages will show up in the job status in (nearly) realtime.
